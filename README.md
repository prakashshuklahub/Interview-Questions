## 🧭 How to use this

Reading solutions is the fastest way to feel like you're learning and the slowest way to actually
learn. The order that works:

1. **Pick a topic below, not a random problem.** Patterns transfer; individual problems don't.
   Doing six sliding-window problems in a row teaches you more than thirty scattered ones.
2. **Read only the statement**, then close the file and attempt it yourself. Give it a genuine
   twenty minutes before looking.
3. **Then compare.** The interesting part isn't whether you got it — it's where your approach
   diverged from the one here, and why.
4. **Watch the [video](https://www.youtube.com/@TheHustlingEngineer)** if the reasoning doesn't
   land. Reading a solution shows you the destination; the walkthrough shows the route.

Where a brute-force approach exists, it's called out alongside the optimal one — because knowing
why the naive answer is too slow is most of what an interviewer is actually probing.
